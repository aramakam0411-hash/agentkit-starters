# Project working notes

Use the filled project brief as the source for the intended user and outcome. User instructions take priority over these starter defaults.

Build the smallest visible version that lets the user try their main task. Keep sample data and simulated integrations clearly labelled. Do not invent customer reviews, prices or results to make a demo look complete.

Before connecting services or deploying, use the user's chosen provider and existing authorization. This starter does not authorize spending money, publishing or contacting people.

After a change, report the useful behavior, what was actually checked and any remaining gap. Preserve the user's work and avoid unrelated rewrites.
