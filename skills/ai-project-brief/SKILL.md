# AI project brief

Preserve the user's idea and chosen tools. Identify the person using the result, the task they want to finish and the output they should see. For an existing brief, fill the actual gaps instead of rewriting settled choices.

Use [the project brief](../../templates/project-brief.md) when a template helps. A fictional worked example is in [the dog walking brief](../../examples/dog-walking/project-brief.md).

Choose a first demo the user can try in one sitting. An agent is useful when the task needs flexible reasoning or tool use; a form or ordinary script may be enough for a simpler task. Explain that choice in terms of the useful result, not a fashionable stack.

Separate supplied business facts from assumptions. Keep missing prices, availability, testimonials and outcome claims unknown. Identify simulated integrations before the build so they do not become false promises.

Ask a focused question only when missing information changes the core result. Otherwise state the assumption and complete the brief. Include one normal example, its expected output and one missing or confusing input. End with the next concrete build step.

This skill produces a brief. It does not authorize deployment, spending, account changes or messages to customers.
